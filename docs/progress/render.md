## Round 7 changes
1. **Game tonnes are labelled as game units.** In `core/overlays.ts` the erosion pressure and erosion risk overlays now use the unit `game t/ha`, and farm productivity uses `game t`. The UI chip, the Overlays panel and the numeric legend labels from `resolveLegend` (for example "High (12 game t/ha+)") all read the unit from here, so they pick it up with no UI change. 2. **WebGL context loss is handled.** New pure module `scene/contextLoss.ts`: `watchContextLoss(canvas, { onLost, onRestored, onGiveUp }, timeoutMs)` listens for `webglcontextlost` (calls `preventDefault` so the browser may restore it) and `webglcontextrestored`, and calls `onGiveUp` if the context is still lost after `CONTEXT_RESTORE_TIMEOUT_MS` (5 seconds). It returns a cleanup that removes both listeners and cancels the timer. `SceneCanvas` stores `gl.domElement` from the Canvas `onCreated` hook in state and attaches the watcher in an effect keyed on that element (so StrictMode remounts reattach it and unmount removes it). While the context is lost it shows "3D view paused, restoring..." over the canvas in a `role="status"` element. On give-up it throws an error during render, so the surrounding `CanvasBoundary` in `App.tsx` switches to the playable `FlatWorld` with reason `crashed` (the compare screen and landing boundaries catch it the same way).
   Tests in `__tests__/contextLoss.test.tsx` mount the real `SceneCanvas` with `<Canvas>` replaced by a stub that calls `onCreated` with a plain canvas, then dispatch the events on that canvas: the status appears on loss and goes away on restore; after a restore no error is raised; a loss that is never restored raises into an error boundary at exactly the timeout; unmount removes the listeners. The watcher itself is also tested directly (preventDefault, timeout edge, cleanup cancels a pending give-up). This is a separate file from `sceneMount.test.tsx` because that file mocks `SceneCanvas` out entirely.

## Round 6 changes
1. **Buildings face the road.** Every building model has its door and front windows on local +Z, and three's `rotation.y = yaw` sends (0, 0, 1) to (sin yaw, 0, cos yaw). `frontYaw(dx, dz) = atan2(dx, dz)` in `core/placement.ts` (exported, tested) now turns the front toward a road neighbour; the old `yawOf(dx, dz)` turned local +X there, 90 degrees off. The random extra quarter turn on 30% of houses is gone; houses keep only a small jitter (plus or minus 0.12 rad). On a corner lot that touches roads on several sides, each house faces the road side nearest to its own offset in the cell, so the house by the east road faces east and the one by the south road faces south. The waterworks hall uses the same rule at its offset. Cells with no road neighbour keep a stable quarter turn.
2. **Preview tiles lie on the drawn facets.** `buildTiles` now uses the terrain mesh's own vertex grid: `TILE_SUB = TERRAIN_SUB` (2), vertices on the cell corners and half-cell lines with heights from the drawn surface, and the terrain's `(k + j) % 2` diagonal rule in global vertex indices with the same winding as `buildTerrainGeometry`. Each tile triangle is therefore a terrain triangle raised by the lift, and can no longer cut under a ridge crease. The 0.03 inset moved into the tile fragment shader (`TILE_INSET`, discards outside the inset and remaps the local coordinate for the edge band). The `inset` parameter of `buildTiles` was removed.
3. **Rain and dust start on the ground.** `Atmosphere` takes an optional `ground` prop (`{ heights, dims }`, passed by `WorldRenderer`). Each frame it samples `heightAt` at the look point (the same `cx, cz` the particles already follow) and sets the rain `uCenter.y` to that ground and the dust to ground plus `DUST_LIFT` (0.4), via `particleBases` in `effects/atmosphereData.ts`. Rain falls from `RAIN_COLUMN` (28) units above it. The base eases toward a new ground height (`easeBase`, rate 4 per second) so panning across a ridge does not make the particles jump; it snaps on a view switch or with reduced motion. The landing sky before a world loads has no terrain and keeps 0.
4. **Runoff arrows: bigger flows are faster.** New pure module `effects/runoffArrowData.ts` holds the size and motion rules, and the shader is built from the same constants. The instance scale is `arrowSize(st) = 0.45 + 0.75 st`; the local slide is `ARROW_TRAVEL / size`, so every chevron travels the same 0.42 world units per cycle (under half a cell, so it stays on its own segment), and the cycle rate is `0.25 + 0.35 st`. World speed now rises with strength (0.105 units/s at the weakest, 0.252 at the strongest) instead of falling.
5. **Rotate orbits.** The rotate command (`rotateCamera`, 45 degrees) now animates the azimuth around the fixed target: `orbitAt(from, angle, e)` in `controls/cameraMath.ts` rotates the start offset about the vertical axis by `angle * e`, so distance and height are constant through the turn. The `Anim` record carries `orbit` for these moves; focus, reset and zoom still interpolate in a straight line.
6. **Overlay type and notes.** `core/overlays.ts` now re-exports the store's `OverlayId` directly (the `| 'urban' | 'susceptibility'` widening is gone). The two UI requests it covered are marked done below.
7. **Compare slider no longer rebuilds overlay textures.** `TerrainMesh` re-applies the overlay when the domain's values change, not when a new `[lo, hi]` array arrives, so moving the compare reveal slider (which re-renders with a fresh array) does no texture work.

## Round 5 changes (record)
1. **Preview tiles respect the whole action (major).** `previewTileStates(validation, count)` in `controls/highlightData.ts` (pure, tested) now feeds the tile shader. A parcel is drawn valid only when its `cellOk` is true AND `validation.ok` is true. When the action as a whole is refused (the engine adds "Not enough budget" and returns `ok: false` while every `cellOk` is true), every tile gets state `TILE_STATE.actionBlocked` (0.25), which the tile shader draws as orange with diagonal stripes, the same as an invalid parcel. Parcels that fail on their own stay 0. So the 3D world and the "Cannot build" status line can no longer disagree.
2. **Overlay colors match the legend.** The terrain shader no longer mixes the overlay into the lit diffuse color or an emissive term. `APPLY` (after `color_fragment`) only samples the overlay and cue textures and works out the ink; a new `POST` block inserted right after `#include <tonemapping_fragment>` mixes `gl_FragColor.rgb` toward the linear overlay color by `amHas`, times a light facet shade (0.8 to 1.0, from a world-space derivative normal against a fixed key light) so relief still reads, then applies the cue ink. Overlay pixels skip both the scene lights and ACES, and `colorspace_fragment` encodes them back to the same sRGB values as the legend swatches (`rampHex`). Fog is applied after this, but round 4 already pushes fog out while an overlay is shown.
3. **The diorama skirt keeps its strata.** `buildTerrainGeometry` adds an `aSurface` attribute (1 on every surface vertex, 0 on the skirt). The vertex shader passes it on as `vAmSurface`, and both `amHas` and the ink weight are multiplied by it, so the overlay color and its hatching stop at the map edge.
4. **Flood water and wetland pools give way to overlays.** `WaterSurface` takes `overlayActive` (passed by `WorldRenderer`) and eases a `uOverlayMix` uniform with the shared `easeOverlayMix` (snaps with reduced motion). The fragment shader multiplies alpha by `1 - 0.8 * uOverlayMix` for wetland (kind 2) and flood (kind 4) water, foam included. Rivers and reservoirs are unchanged, since those cells are no data on most overlays.
5. **Camera inertia respects reduced motion.** `CameraRig` sets `controls.enableDamping = !reducedMotion` when it configures the controls and again every frame, so toggling the setting takes effect at once. The rig also publishes its MapControls as the R3F root's `controls` (like drei's `makeDefault`), cleared on unmount, which is how the test reads it.

## Round 4 changes (record)
1. **Tree and bush counts no longer follow the seasonal greenness swing.** The sim moves every cover toward a season-specific target (forest 0.92 wet, 0.88 dry; grassland 0.68 and 0.45), so raw `vegetation` dips each dry season without any plant being lost. `seasonFreeVegetation(cover, veg, season)` in `core/placement.ts` divides by the season's target from `VEG.target` and multiplies by the wet target, which cancels that swing. Plant presence reads this value and saturates: forest has its full count at 0.66 or more (`FULL_STAND_VEG`, `forestTreeCount`), grassland bushes, shrubs and lone trees at 0.5, wetland reeds at 0.7. Healthy stands sit well above those (seed 7: forest 0.75 to 0.80, grassland 0.56 to 0.59), so only real decline thins them. The seasonal swing still shows through foliage tint and the existing `0.85 + 0.15 * veg` tree scale. Bare-ground stones now follow soil loss (`1 - soilHealth`, which persists) instead of this season's erosion, which came and went with the rains. Probe (seed 7, 12 seasons): on the valley 0 vegetation slots toggle between any two normal seasons (was 239 forest slots plus grassland); on Kaani 0 forest slots and 1 to 3 of about 2200 grassland cells (degraded parcels sitting exactly at a slot threshold). Drought seasons still thin grass and reeds, because the model really does lose cover there.
2. **Props give way to overlays.** Prop materials are now created per view (`createPropMaterials()` in `props/materials.ts`), each set with its own `uOverlayMix` uniform, so a compare view's overlay never ghosts another view. While an overlay is on, the vertex shader shrinks every prop toward its base (trees keep 18% of their height and 55% of their width, houses 30% and 90%, crop rows and terraces 50% and 60%) and the color fades toward a pale warm grey (75% for plants, 65% for buildings). Roads only fade (45%), since they are flat and help orientation. Prop shadows switch off while an overlay is shown, because the shadow pass would still draw full-height trees. The mix eases with the same rule as the terrain overlay (`core/overlayFade.ts`, shared by terrain, props and fog) and snaps with reduced motion.
3. **Fog no longer washes overlay colors.** `overlayFogRange(near, far, extent, mix)` in `effects/atmosphereData.ts` pushes fog near beyond the farthest point the camera can see (`maxDistance + 2 * sqrt 2 * extent`, 195 units on a 64 map) at full overlay mix, so overlay pixels are never fogged, in heavy rain and drought included. Rain streaks and dust are thinned by 60% over an overlay. The fog eases back when the overlay closes.
4. **Cursor announcement follows the view.** `cursorAnnouncement` (`controls/announce.ts`) is given `viewSnapshot.layers` when a past snapshot is shown, and adds "(past view)". The terrain is shared.
5. **Runoff cue matches its colors.** The runoff overlay's color-independent cue is now a new terrain shader pattern, wavy lines (cue code 8, `pattern: 'waves'`), whose weight follows the same normalised `fields.runoffMm` as the colors, so a parcel with heavy local runoff but little upstream flow carries a bold pattern. The flow arrows stay as a separate cue for `flowMm`; the overlay and cue descriptions say which is which.
6. **WaterSurface render is pure.** The memo builds the mesh from its inputs plus the field of the build on screen, read from a ref that is only written in a `useLayoutEffect` after commit (which also resets the tween). A repeated or discarded render (StrictMode) gets the same mesh, so draining cells keep their one-build fade. The memo returns plain arrays; the `BufferGeometry` is made in its own memo and disposed on change.
7. **Resource hygiene.** RunoffArrows disposes its InstancedMesh when the mesh changes and the shared arrow geometry and material only on unmount. `DynamicGeometry` calls `geometry.dispose()` before swapping in bigger buffers, so three frees the old GPU buffers and uploads the new ones on the next render.

The local 16/20/8 constants are deleted. A test checks that each cover reaches full visual size at exactly `VEG.matureSeasons[cover]` and is smaller one season earlier.
4. **Rivers react to flow and sediment.**
   - Stage: `riverStage(frame)` is last season's `flowMm / bankfullMm` on each channel cell over a fixed display reference (`FLOW_STAGE_REF = 3`), averaged over neighbouring channel cells so the surface does not step. River depth is `0.17 * (0.3 + 0.9 * stage)` above the bed, so it never rises more than 0.2 units (the banks stay dry at their centres). The existing level tween animates it. Measured mean stage on the channels (seed 7): valley wet 0.48 to 0.54, dry 0.17 to 0.21, heavy rain 1.00, drought dry 0.08; Kaani wet 0.53 to 0.58, heavy rain 1.00, drought dry 0.11.
   - Turbidity: `waterTurbidity(frame)` is `sedimentFlux` over the water passing the cell (`flowMm` over the cell area, floored at 5 mm), on a log scale between fixed clear and muddy references (`TURBIDITY_CLEAR = 100`, `TURBIDITY_MUDDY = 20000` in game "g/m3"). It reaches the shader as `aTurbidity`/`aTurbidityFrom` (tweened like the level) and mixes the water toward a muddy brown and makes it more opaque. The same reference is used on every world, so Kaani's rivers, which the model makes far more sediment-laden, look browner than the valley's (mean channel turbidity 0.44 to 0.82 vs 0.12 to 0.37).
   - Silt fans: a pale silt strip on land cells where `sedimentIn` passed 40% of `SILT_VISUAL_REF = 80` last season (39 to 57 cells in a normal valley wet season, 432 in its heavy-rain season, none in dry seasons).
   - Not done: the reservoir bed does not rise with `reservoirSiltM3` (the brief marked it optional; the silt total is per map, not per basin).
5. **The real scene graph is mounted in a test.** `sceneMount.test.tsx` renders through R3F's `createRoot` on a detached jsdom canvas with a stub renderer, `frameloop: 'never'` and a fixed size, and drives frames with `advance()`. Only `SceneCanvas`, the DOM wrapper around `<Canvas>`, is replaced by a pass-through. It checks: `WorldRenderer` builds terrain, water, all prop layers, sky and runoff arrows and calls `gl.render`; vegetation and building instance counts equal `countKind` of the placement targets; the store overlay fades `uOverlayMix` in over several frames and back out; clearing forest shrinks trees away over frames and settles on the new count; with reduced motion a change and an overlay snap in one frame; unmount disposes the terrain and water geometry and materials. `GameScene` mounts with camera, picking and highlights at low quality (2 trees per forest cell), draws the selection outline, moves the camera for an explicit focus request and clears it, ignores a cursor move next to the centred cell, and switches to a snapshot. `SnapshotView` mounts read-only with an overlay. `LandingScene` with an explicit `world` shows only the sky first, builds the world after the idle callback and orbits.
6. **Snapshot reservoir fill.** `frameFromSnapshot` uses `snapshot.reservoirM3 / snapshot.totals.reservoirCapacityM3` when the caller passes no fill (null when there are no reservoirs, never a made-up level); a passed value still overrides it. `reservoirFillForSnapshot` also prefers the snapshot's own storage and falls back to history. Compare views now show real reservoir levels without any UI change.
7. **Camera follow vs focus.** `planFocus` (pure, in `controls/cameraMath.ts`) decides the move. When `focusCell` equals `cursorCell` (the keyboard cursor), the camera keeps its distance and direction, does nothing while the cell projects inside the central 60% of the view, and otherwise pans just far enough to bring it back to that edge (0.35 s). Other requests (explanations, "show on map") centre the cell and come in to 32 units or closer (0.9 s). A follow that needs no move clears `focusCell` without touching a running animation.
8. **Buffer churn.** Highlights use `DynamicGeometry` (`controls/dynamicGeometry.ts`): preallocated dynamic buffers written in place with update ranges and a draw range, growing by doubling. Runoff arrows allocate `aPhase`/`aStrength` once at map size and write in place. `writeVertexColors` reuses three per-cell channel arrays stored on the `TerrainGrid`. The mesh vertex-height cache is a WeakMap on the heights array with an array per subdivision count, so `heightAt` does no string building.
9. **Water diagonals.** Shared-surface and reservoir quads use the terrain's `(k + j) % 2` diagonal rule. A test interpolates `aGround` at the centre of every water quad of the valley and finds it equal to `meshHeightAt`.
10. **Colorblind setting.** `WorldRenderer` reads the store's `colorblind` flag and passes it to the terrain and prop layers. When on, damage moves along a light/dark and yellow/blue axis instead of green to ochre to red: degraded soil and drought turn pale straw (lighter), erosion and gullies dark slate blue (darker, and mixed in more strongly), rock lighter grey, stressed foliage pale yellow, dead foliage and failed crops dark blue-grey. Tests check that the tints change, that degraded land is clearly lighter than healthy land and gullied land clearly darker, and that trees and crops use the new tints.

Also added this round: the two SPEC overlays that were missing.

## The renderer (current)

### Public API (`src/game/index.ts`)
- `<GameScene />`: the interactive world. It fills its parent. It shows `store.viewSnapshot` read-only when that is set (hover and inspect still work, tools are off).
- `<LandingScene world? worldId? seed? />`: a slow cinematic orbit over the live world, or, when no game is loaded, over the starting state of `world`, or of `worldId` (default `DEFAULT_WORLD_ID`). The state is built in an idle callback; the sky shows until it is ready. Still with reduced motion.
- `<SnapshotView snapshot terrain syncGroup? cameraState? onCameraChange? weather? reservoirFill? overlay? overlayDomain? label? />`: a read-only past snapshot. Views that share a `syncGroup` share one camera. Stack two views and clip one with CSS for a before/after slider.
- `OVERLAYS` (keyed by every overlay id), `OVERLAY_IDS`, `resolveLegend(id, domain)`, `overlayDomain`, `overlayValues`, `RAMPS`, `rampHex`, type `WorldOverlayId`. Each `OverlayDef` has `id, label, description, unit, valueKind, source, ramp, domain, higherIs, cue {pattern, description, follows}, legend [{t, color, label, pattern?}], noDataLabel?`.
- Snapshot helpers: `weatherForSnapshot(sim.weather, snap, index?)`, `reservoirFillForSnapshot(sim.history, snap, index?)`, `sharedOverlayDomain(id, snapshots, terrain)`, `seasonIndex`, `snapshotKey`.
- Camera commands: `resetCamera()`, `zoomCamera(±1)`, `rotateCamera(±1)`, `defaultCameraState`, `CameraState`.
- Also `brushCells`, `lineCells`, `toolMode`, `cellToWorld`, `worldToCell`, `frameFromSim`, `frameFromSnapshot`.

### World
- Terrain: a shared-vertex heightfield, 2 subdivisions per cell on every quality level, bilinear heights with 2.2x vertical exaggeration, flat-shaded facets with alternating diagonals and an earthy diorama skirt. Vertex colors are bilinear blends of per-cell ground colors. The palette is warm (sage, olive, straw, ochre, terracotta, dusty plaster). Low `soilHealth` drifts toward ochre and terracotta, erosion toward gully red, steep slopes toward rock, water stress plus dry season or drought toward straw (or the colorblind tints above). Color changes blend over about 1 s.
- Water: river and lake surfaces on channel and water cells, extended one cell toward the banks but held below each dry cell's own ground. Stage follows flow, color follows turbidity (see change 4). Depth tint, ripples drifting along each cell's D8 `flowTo`, shoreline foam, fresnel sky tint and a sun glint that follow the weather mood. Wetland pools follow `layers.wetlandStoreMm`. Reservoirs are flat per basin between bed and rim, following `reservoirM3 / totals.reservoirCapacityM3`, inside an earth embankment. Flood water is drawn on `fields.flooded` cells with depth from `fields.floodDepthM` (seed 7: 7 cells in the valley's heavy-rain season, step 7; 23 cells on Kaani). Levels and turbidity tween over 1 s.
- Vegetation: 7 CC0 Kenney tree models plus bushes, stumps, rocks and lilies, and procedural reeds, all instanced. Tree count per forest cell follows the season-free vegetation (round 4 change 1), size follows the model's maturity, species follow elevation. Clearing removes trees and leaves stumps where forest stood (`baselineCover`). Foliage tint follows `waterFactor`, season and soil. Wind sway in the vertex shader, off with reduced motion.
- Farms: crop rows per cropland cell by intensity (3 patchy, 4, or 5 dense rows), colored and sized by `waterFactor` and `yieldT`; stubble when the season's harvest is zero; a blue ditch on irrigated fields; contour terraces on conservation cells; a fruit-tree row on agroforestry.
- Settlement: houses by `structureLevel` (2 cottages, 3 two-storey houses, 4 buildings with apartment blocks) with their doors toward the adjacent road (on corner lots, the road nearest each house); connected road pads and arms; waterworks and markets.
- Erosion: gully streaks along the flow direction where this season's `fields.erosion` is high or degraded soil sits on a slope, stones on bare ground that has lost its soil, terrain tint, and silt fans where sediment settled.
- Atmosphere: hemisphere fill plus a warm sun with 2048 px filtered shadows covering the map (off on low quality, and for props while an overlay is on), gradient sky dome and fog (pushed past the map while an overlay is on). Mood follows the season and the last simulated `WeatherSeason.kind` (rain streaks in heavy rain, dust haze in drought), blended over a few seconds. No day cycle (optional in the brief).

### Overlays
While an overlay is on, props shrink and fade and the fog clears (round 4 changes 2 and 3). Every overlay has a colorblind-safe ramp (viridis, cividis, inferno without its black end, ColorBrewer blues, Okabe-Ito for land cover) and a cue that does not depend on color: land cover per-category patterns; elevation contour lines; slope and sensitivity hatching; erosion pressure and erosion risk cross-hatching; runoff wavy lines that follow local runoff, plus animated chevrons along `flowTo` sized by flow; soil and moisture dots that grow as conditions get worse; productivity row lines; urban development a street grid. Land cover samples its texture nearest. Overlay colors are painted after tone mapping (round 5 change 2), so they match the legend; the map's skirt and the round 5 flood and wetland fade keep them visible and on the surface only. Model outputs show no data until the first season has run.

### Interaction and camera
- Picking marches the camera ray through the drawn height field with bisection, at most once per frame.
- Hover outline (inspect), pulsing gold selection outline, wide white ring for the store's `cursorCell`. Tool preview tiles from `preview.validation`: blue only when the parcel and the whole action pass, orange with diagonal stripes for an invalid parcel or a refused action (for example over budget), neutral white until validated.
- Click to apply; paint tools drag a brush; road drags a 4-connected line; the store validates and applies (`setPreviewCells`, `commitCells`).
- MapControls: inspect tool left-drag pans; build tools left-drag paints, right-drag rotates, middle-drag or shift+right pans; wheel zooms; Space over the world pans with left-drag in any mode; history view pans with left-drag. Keys: W A S D pan, Q E rotate, - and = zoom, Home resets (ignored in dialogs, fields, scrollable panels, while a modal or the end report is open, and off the game screen). Limits: distance 9 to 105, polar 0.18 to 1.18 rad, target clamped to the map, camera 1.2 units above the terrain. Focus behaviour as in round 3 change 7. Drag inertia (damping) is off under reduced motion.

### Performance
- Everything repeated is instanced with shared geometry and one material set per view; per-kind instance buffers grow on demand; a settled world does no per-frame buffer work; targets are recomputed only when the layers or fields they read change.
- React re-renders only when `sim`, `viewSnapshot`, `viewStep`, `quality`, `overlay` or `colorblind` change. Hover, preview, selection, tool, focus and reduced motion go through zustand subscriptions into refs.
- Low quality: no shadows, pixel ratio 1, no antialiasing on a fresh canvas, 2 trees per forest cell instead of 4, fewer particles, every other runoff arrow.
- `?debug` shows FPS, worst frame, draw calls, triangles, geometries, textures and instance counts.

## Decisions
- Kenney Nature Kit 2.1 (CC0), license verified, 12 GLBs in `public/assets/kenney-nature-kit/`, listed in `public/assets/LICENSES.md`. Merged per model and recolored into our palette at load; procedural fallbacks until they load or if they fail. Houses, infrastructure and crops are procedural in the same flat-shaded style.
- Weather indexing follows the engine: after `step` steps the last simulated season is `weather[step - 1]`; step 0 is calm.
- Display references are fixed, not per frame, so the same state looks the same in every season (`core/visualRefs.ts`): `EROSION_VISUAL_REF = 25`, `WETLAND_POOL_REF_MM = 150`, `FLOOD_VISUAL_REF_M = 2`, `FLOW_STAGE_REF = 3`, `TURBIDITY_CLEAR = 100`, `TURBIDITY_MUDDY = 20000`, `TURBIDITY_MIN_FLOW_MM = 5`, `SILT_VISUAL_REF = 80`, `SILT_FAN_MIN = 0.4`. They are art-direction choices that map model outputs to visuals, not model parameters. Adaptive overlay legends scale to the 98th percentile with floors.
- Interactive canvases use `role="application"`, are focusable and describe their keys; passive views use `role="img"`.
- The colorblind flag changes the world's own state tints (change 10). Overlays and the tool preview were already colorblind-safe and stay the same either way.
- three r186 removed `PCFSoftShadowMap`, so we use `PCFShadowMap` with `shadow.radius = 3`.

## Known gaps and risks
- The overlay's facet shade uses a fixed key light (the default sun direction), not the current mood's sun, so overlay relief shading does not change with season. That is deliberate: legend colors stay put.
- Ghosting amounts (prop shrink and fade over overlays) and the runoff wave weight are tuned on paper, not on screen; they are constants in `OVERLAY_GHOST` and the shader's cue 8.
- On Kaani 1 to 3 degraded grassland parcels (of about 2200) still gain or lose a bush between normal seasons, because their season-free value sits right at a slot threshold and the model's cover lags its target slightly.
- Not yet seen in a browser. Most likely to need tuning on the first playtest: shadow bias on the low-poly terrain, overlay ink contrast, water foam width, how brown Kaani's rivers look, crop row height on steep fields, tree density on weaker laptops (measure with `?debug`).
- No GLSL compiler was available, so shader syntax was reviewed by hand; the scene mount test runs every component but the stub renderer does not compile shaders.
- `antialias` cannot change on a live WebGL context, so switching quality changes everything except antialiasing until the canvas remounts.
- The reservoir bed does not show trapped silt (see change 4).
- Building a landing state costs 100 to 200 ms in an idle callback (the engine has no cheaper way to build initial layers).
- `SceneCanvas` is mounted in tests only with `<Canvas>` stubbed (`contextLoss.test.tsx`); jsdom has no WebGL. Real context restoration (three.js rebuilding programs and textures) has not been exercised.
- If a context is lost on the landing screen and never restored, its boundary has `fallback={null}`, so the landing just loses its backdrop.
