4. **Inspector provenance.** On real-data maps there is a row "Observed (ESA WorldCover 10 m 2021)" read from `world.details.observedCover` through the typed accessor `worldCellData` in `src/state/worlds.ts`, and the game start is labelled "At the start of the game". Where they differ, a note gives the documented rule for that cell (stream channel set to water, road, or a built-up share quoted from `details.builtPct`). Sections carry a kind chip: Terrain is "Observed baseline data" on real maps (with the DEM name and the pit-filling caveat) and "Fictional map" otherwise; soil, water and last-season values are "Illustrative model output"; sensitivity is "Derived indicator". Every hint is now an accessible Tip on a focusable info button instead of a `title`.
5. **Play Scenario B keeps A's later seasons.** If run A went on after it was saved (later step or more decisions), `branchScenarioB` re-saves A at the current point first and says so in the feedback line, naming both dates.
6. **Keyboard parcel cursor.** Shift plus an arrow moves `cursorCell` (starting at the middle of the village, else the map centre), selects the parcel, asks the camera to follow, and previews the active tool with the same cells the pointer would use (`toolCellsAt`). Enter applies the tool (`commitCursor`); since round 4 Shift+arrows also move focus to the cursor read-out so Enter is never taken by a focused button. Escape drops the cursor and its preview. The status line reads out the parcel name, validity, cost and "press Enter to build". Keys are listed in Settings and help.
7. **Tutorial** now says "Blue tiles mean you can build there. Orange striped tiles mean you cannot, and the bar at the bottom of the screen says why and what it costs, in words."
8. **Compare Futures.** (a) A legend under the landscapes from the renderer's `resolveLegend(overlay, sharedDomain)` (added to `SnapshotHelpers` in `gameModules.ts`) plus the non-color cue; the flat fallback shows a land-cover legend, and the overlay picker hides when only the flat map is available. (b) Every chart line can be compared: charts with several lines get a line picker, so water security, food needed, debt, housing capacity and the harvest factors are all comparable. (c) `RunData.explanations` (store explanations for B and for a saved A, replay output for a rebuilt A); a "Why" section shows each run's explanations for the chosen season side by side with their evidence tables (reusing `ExplanationCard`).
9. **Decisions in history.** Decision markers are labelled buttons ("Year 3 wet: built housing on 4 parcels for $8,000") that jump the scrubber to the season that shows them in place. The past banner lists what was decided in the season shown (phrase, parcels, cost, one-off revenue) with "Show on map", and a button to that season's insights. Insights filters to the viewed season (with "Show all seasons", which then outlines that season's entries). Explanations are matched to seasons by the engine's `s<step>-` id prefix.
10. **Speeds**: `SPEED_MS` is 2400, 1200 and 600 ms per season, and labels are derived from it (`speedLabel`), so 1x, 2x and 4x are exact.
11. **Redo while viewing the past** returns early with the same message as undo and keeps the redo stack; the stack is cleared only when the engine itself rejects the action. `commitCells` moves the selection only when the action succeeded.
12. **Focus.** `useFocusTrap` (`src/ui/common/useFocusTrap.ts`) traps Tab in the end report, marks everything else inert, and returns focus to the opener (or the Report button). World picker cards show a focus ring through `has-[:focus-visible]` plus a CSS fallback.
13. **Color-independent cues.** Chart weather bands have a pattern (diagonal for drought, vertical for heavy rain, dots for good seasons) and a letter (D, R, G); chart tables have a Weather column. The scrubber's `aria-valuetext` names drought or heavy rain. Compare marks the better value with a check icon and screen-reader text.
14. **Labels.** Rainfall has its own kind, "Generated from the seed". Each chart carries the kind of its metric instead of a blanket "illustrative" line. Settings summarises the key model assumptions inline (from `docs/MODEL_ASSUMPTIONS.md` section 12) instead of pointing to a file the player cannot reach. The Insights badge counts only explanations newer than the last visit (`seenExplanations`).
15. **No WebGL is still playable.** The game shows a flat map of the live valley (`src/ui/map/FlatMap.tsx`) with hover preview (blue valid, orange striped invalid), click to inspect, click or drag to build (roads as lines), plain arrow keys for the cursor and Enter to build, plus an accurate note on what is missing (overlays). The same fallback is used when the 3D view crashes or is absent.
16. **Goals come only from the simulation.** `src/state/objectives.ts` imports `evaluateObjectives` and `endReport` from `src/simulation/scenarios/guided` directly. The fallback goals and module discovery are gone. If evaluation throws, the Goals panel and chip say "Goals unavailable" instead of showing different goals.

## Decisions
- Round 3: a partial stroke is applied as the trimmed action so the engine's own decision record is right everywhere it is read (markers, banner, report, drought attribution, compare), instead of patching each reader. Saves made before this round still hold full strokes; replay gives the same state (the engine skips invalid parcels either way), only their old records keep the requested count.
- Round 3: when exit cannot save, the player stays in game rather than losing the run silently; a second press is the explicit "leave anyway".
- Shift plus arrows for the cursor because the camera owns plain arrows and W A S D. The store handler prevents the default, which the camera rig treats as "not mine" (`keyBlocksCamera`), so the camera does not pan at the same time. On the flat map, plain arrows move the cursor, because there is no camera there.
- Snapshot k is described everywhere as "after year Y, season" (the season that ended in it). The top bar, scrubber, past banner, Insights filter and Compare all use that, and decisions made during season k - 1 are the ones "in place" in snapshot k.
